# /oasis-plan

1. Restate the requested outcome and acceptance criteria.
2. Inspect repository status and relevant solution/project files.
3. Trace the existing implementation from UI/component through service/API, Shared contracts, server logic, and persistence as applicable.
4. Identify package/framework constraints and similar implementations.
5. List proposed files to change, design choices, risks, and test strategy.
6. Separate confirmed facts from assumptions.
7. Do not edit files in this workflow.
8. End with a small, ordered plan and any decision that needs user approval.
